# ISP/ISMP의 논리 연결

ISP는 환경·현황 분석, 전략, 목표모델, 이행계획을 연결한다. ISMP는 구체적인 대상의 방향과 업무·기술 요건을 분석하여 구조·상세 요구사항·사업계획으로 연결한다. 이 스킬은 그 흐름을 일반 연구에도 적용하도록 재구성했다. 정식 사업 기준은 해당 기관의 적용 문서로 별도 확인한다.

## 질문에서 판단까지

사용자 요청에 없는 목표를 대신 정하지 않는다. 요청을 실제로 지원하는 판단 기준을 먼저 정하고 자료를 통해 보완한다. 특정 대안이 유리해 보인다는 이유로 비교 기준을 바꾸지 않는다. 기준 변경이 필요하면 이유와 결과에 미친 영향을 기록한다.

현재 상태를 직접 관찰할 수 있는 과제에서는 사용자 자료·현행 코드·운영 결과를 확인한다. 공개 자료만으로 사용자의 현행 상태를 추정하여 확정하지 않는다. 지식 조사에서는 현재 알려진 주장과 논쟁을 현황으로 사용한다.

진단은 현상·가능한 원인·입증된 원인을 구분한다. 같은 원인에서 비롯된 여러 증상을 묶고, 원인과 해결책이 실제로 연결되는지 검토한다. 근거가 부족한 원인은 가설로 남긴다.

## 대안과 목표안

결정을 지원하는 과제에서는 실행 가능한 대안과 현행 유지·부분 개선을 검토한다. 형식적인 대안 개수를 채우지 않는다. 각 대안에 목적 적합성, 증거 강도, 적용 조건, 제약, 비용·노력·위험을 대응시킨다. 수치 가중치는 근거와 민감도가 있을 때 사용한다.

목표안에는 채택 이유, 대안별 기각 이유, 핵심 가정, 조건이 달라졌을 때의 선택을 설명한다. 여러 안을 조합할 때 구성요소 사이의 호환성과 운영 부담을 검토한다. 한 부분의 장점이 전체의 성공을 증명하지 않는다.

## 요구사항과 이행

실행 목적에서는 다음 항목을 필요한 만큼 상세화한다.

| 요소 | 작성할 내용 |
|---|---|
| 기능·업무 | 사용자·운영자가 어떤 조건에서 어떤 행동과 결과를 기대하는지 |
| 데이터·연계 | 입력·출력·소유·품질·갱신·외부 연결 및 기존 자산 활용 |
| 품질·운영 | 성능·신뢰성·접근·보안·유지보수의 관찰 가능한 수용 기준 |
| 제약·의존 | 선행 과제, 환경, 필요한 허가·자료·역량 |
| 검증 | 어떤 자료·실험·관찰이 요구사항 충족을 확인하는지 |
| 이행 | 순서, 담당 역할, 자원 산정의 근거, 성공·중단·재검토 조건 |

요구사항은 `trace.jsonl`에 근거 질문·주장 또는 상위 판단을 부모로 연결한다. 실행 과제는 관련 요구사항과 수용 기준을 포함한다. 같은 과제가 여러 문제를 해결할 때 관계를 모두 기록하되 중복 과제를 만들지 않는다.

설명·학술 조사에서 실행안을 요청하지 않았다면 결과의 적용 범위와 후속 확인 사항까지만 제시한다. 알 수 없는 비용·담당자·기간을 형식에 맞추기 위해 만들지 않는다.

## 추적성 점검

최종 판단에서 원래 질문과 출처까지 거슬러 올라갈 수 있는지 확인한다. 반대로 중요한 질문이 보고서에서 답변되었거나 명시적으로 미확정 처리되었는지 확인한다. 요구사항·과제에서 근거가 사라지면 해당 항목을 재검토한다. 단순한 ID 연결 검사는 필요조건이며 의미상 연결은 실제로 읽고 검토한다.
