# 실증 연구와 실험 계보

문헌만으로 판단할 수 없고 실험·재현·실측이 질문에 답하는 경우에 적용한다. 연구 요청이 자료 조사만 허용한다면 필요한 실험과 미확정 사항을 제시한다. 클라우드 작업·외부 공급자·프로젝트 변경·비용 발생을 방법론 자체가 허용하지 않는다. 이미 승인된 실행 범위에서는 그 범위를 재확인받지 않고 진행한다.

## 가설과 비교 계약

실행 전에 다음을 정하고 `evidence/` 안의 프로토콜 기록에 보존한다.

| 항목 | 기록할 내용 |
|---|---|
| 질문·가설 | 어떤 주장을 어떤 결과로 지지·반박할 것인가 |
| 기준선 | 비교할 현재 방식과 코드·설정·입력 버전 |
| 변경 변수 | 이번 비교에서 의도적으로 바꿀 요소와 이유 |
| 고정 조건 | 비변경 코드·데이터·평가 정의·실행 환경·측정 구간 |
| 판정 | 주 지표, 최소 수용 기준, 오차·변동성 판단, 필요한 반복·대조 |
| 실행 방법 | 실제 명령·유효 설정·환경을 재현할 수 있는 기록 |
| 증거 | 원시 로그·최종 수치·예외·관련 중간 경과·산출물 위치 |

변경 변수를 제외한 조건을 맞춰 비교한다. 환경 자체가 연구 대상이면 그 차이를 의도한 변수로 선언한다. 환경변수·실행 명령을 사용했다는 이유만으로 금지하지 않으며, 중요한 것은 비교 조건이 추적되고 재현되는지다. 코드·설정·명령·환경의 실제 유효값을 함께 기록한다.

평가 기준이나 입력을 바꾸어야 한다면 새 프로토콜 버전으로 구분한다. 서로 다른 기준으로 측정한 수치를 같은 비교군의 승패로 처리하지 않는다. 검증 자료의 누수, 유리한 표본 선택, 한 번의 우연한 최고값을 점검한다. 필요한 반복 횟수는 변동성과 질문에 맞추며 고정 횟수만으로 신뢰성을 주장하지 않는다.

## 결과를 축적하는 구조

같은 결정의 대안은 공통 기준선 아래의 비교 후보로 둔다. 한 결과가 다음 가설의 전제를 제공하면 그 결과를 부모로 연결한다. 다음 실험을 만들기 전에 ‘부모 결과의 무엇을 유지하고 무엇을 바꾸는가’를 설명한다. 서로 관련 없는 가설을 억지로 한 줄에 연결하지 않는다.

결과가 나온 실험은 당시의 코드·조건·입력·로그·해석을 보존한다. 후속 아이디어는 새로운 기록으로 만들고 기존 결과를 덮어쓰지 않는다. 불리한 결과도 동일하게 보존한다. 결과의 해석을 정정하면 기존 기록과 정정 이유를 연결한다. Git이 있는 환경에서는 커밋과 작업 사본을, 없는 환경에서는 버전·파일 해시·별도 결과 디렉터리를 사용한다.

선택한 후보는 검증된 개선과 성립 조건을 가진 다음 비교의 기준선이 될 수 있다. 이전 대안과 반대 증거를 남겨 재검토할 수 있게 한다. 이 실험 계보는 일반 문헌 탐색의 범위를 좁히는 규칙이 아니다.

## 실행 결과 분류

| 상황 | 처리 |
|---|---|
| 환경·의존성·실행 오류로 가설을 시험하지 못함 | 운영 오류로 기록하고 허용된 범위에서 복구. 과학적 반증이나 개선으로 세지 않음 |
| 정해진 조건에서 기대보다 나쁘거나 목표를 충족하지 못함 | 유효한 부정 결과로 보존. 유리한 값이 나올 때까지 같은 결과를 덮어쓰지 않음 |
| 메모리·시간 제약이 연구 대상인데 그 제약을 초과함 | 해당 질문에 대한 실제 결과로 기록. 단순 운영 오류로 숨기지 않음 |
| 수치가 나왔지만 측정 정의·입력·로그가 불명확함 | 판단 유보. 재현·추가 증거를 확보하기 전까지 채택하지 않음 |
| 비교 조건과 증거가 맞고 효과가 확인됨 | 적용 조건·변동성·대안과 함께 판단하고 다음 가설로 연결 |

운영 오류의 복구와 가설 변경을 구분한다. 반복 실패의 이유가 같으면 공통 설정 원인을 조사하고, 의미 없는 재실행을 계속하지 않는다. 시도·검색·실험의 고정 개수를 자동 종료나 사용자 승인 기준으로 삼지 않는다. 새로운 시도가 판단을 바꿀 수 있는지와 사용자의 범위·자원을 기준으로 진행한다.

## 실제 결과를 확인하는 증거

실행 결과에는 실제 사용한 변형·설정, 최종 지표와 단위, 간단한 결과 요약을 남긴다. 긴 실행은 판정을 설명하는 중간 경과도 확인 가능하게 보존한다. 프로세스 종료 코드나 ‘완료’ 상태만으로 연구 결과를 추정하지 않는다.

로그를 읽을 때 확인한 구간과 전체 길이를 구분한다. 화면에 잘려 보이지 않는다고 해당 수치나 오류가 없다고 결론내리지 않는다. 관련 구간을 추가로 읽고 최종 결과·설정·예외가 서로 맞는지 대조한다. 그래프·표·산출물도 해당 코드·입력·실행과 연결한다.

## 기존 장부에 연결

새 데이터베이스나 필수 실행기는 추가하지 않는다. 기존 연구 기록으로 다음을 표현한다.

- `questions.jsonl`: 실험이 답할 질문과 적용 조건·깊이 조사.
- `trace.jsonl`: 가설·후보를 `option`, 비교 판단을 `decision`, 고정 평가 조건을 `requirement`, 실제 실행 계획을 `action`으로 연결.
- `sources.jsonl`과 `evidence/`: 프로토콜·코드/환경 식별·실제 로그/결과를 기록. 검증에 필요한 파일은 각각 등록하거나 필요한 실제 증거를 하나의 제한된 증거 파일에 포함. 파일 경로만 적은 노트를 원본 증거 전체를 보존한 것으로 표현하지 않음.
- `claims.jsonl`: 직접 측정은 `observed`, 문헌에서 가져온 실험은 `source_claim`, 여러 결과를 연결한 판단은 `inference`로 구분.
- `leads.jsonl`: 재현 불가·상충 결과·추가 대조의 필요와 처리 상태.
- `reviews.jsonl`: 비교의 공정성, 평가 변경, 유효한 부정 결과의 보존, 해석과 원시 결과의 일치 여부 점검.

자동 검증기는 등록된 파일과 관계의 일관성을 검사한다. 비교의 공정성이나 과거 실험이 실제로 수정되지 않았는지의 전체 이력을 독자적으로 보증하지 않는다. 이 부분은 버전·로그와 검토 기록을 확인한다.
